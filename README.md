# sp6-2_smart-table_starter

Интерактивное веб-приложение для мониторинга, анализа и управления записями о торговых операциях. Проект реализован в рамках двух последовательных этапов (Проектных работ).

---

## Стек технологий
* **JavaScript (ES6+)** — модульная архитектура, асинхронное программирование (`async/await`, `Promises`).
* **HTML5 / CSS3** — семантическая разметка, БЭМ-архитектура стилей, валидация форм.
* **Vite** — сборщик проекта и инструмент для локального развертывания.

---

## История разработки и ключевые этапы

### Локальная обработка и UI-компоненты
На первом этапе была создана клиентская логика приложения, работающая на базе синхронных вычислений с локальным массивом данных (In-Memory).

* **Модульная архитектура:** Реализовано разделение интерфейса на изолированные UI-компоненты (таблица, пагинатор, поиск, сортировка, фильтрация).
* **Клиентская фильтрация и поиск:** Написана сквозная логика текстового поиска и фильтрации строк по продавцам.
* **Кастомная сортировка:** Реализован циклический механизм переключения режимов сортировки колонок (`none` -> `asc` -> `desc`) с использованием паттерна стейт-менеджмента и карт соответствия (`sortMap`).
* **Пагинация данных:** Написан алгоритм динамического расчета диапазонов вывода строк и генерации кнопок страниц на основе размера локального массива.

---

### Интеграция с API и серверный рефакторинг
Второй этап был полностью посвящен глобальному архитектурному рефакторингу — переходу от обработки данных в памяти браузера к клиент-серверному взаимодействию.

* **Асинхронный рефакторинг (API):** Прямая работа компонентов с массивами данных заменена на работу с состоянием асинхронных запросов через `fetch` и `async/await`.
* **Параллельная загрузка (Promise.all):** Реализовано кэширование и параллельное скачивание справочников продавцов и покупателей с помощью `Promise.all` для оптимизации сетевого трафика.
* **Переход на Query-параметры:** Локальные цепочки фильтрации и сортировки полностью удалены. Вместо этого компоненты переписаны на мутацию единого объекта Query-параметров (`search`, `filter[...]`, `sort`, `page`, `limit`) для отправки на сервер.
* **Оптимистичный UI и реактивная пагинация:** Перерисовка пагинатора и элементов навигации переведена на реактивную модель на основе мета-данных (`total`, `pages`), возвращаемых сервером в реальном времени.
